>
> **Языковые версии:** [English](Home_Console_Raspberry_Pi_Plan_EN.md) · [Русский](Home_Console_Raspberry_Pi_Plan_RU.md). При изменении решений, объёма работ, этапов или критериев приёмки обновлять обе версии одновременно.
>
> **Основная идея:** Создать одну выделенную панель Home Assistant (`Home Console`) с шестью представлениями, адаптированными для 5-дюймового сенсорного экрана Pi `1024×600`, и привести в порядок отдельную адаптивную основную панель HA для обычного использования с ПК и телефона. Сохранить существующий стек NUT и киоск `cage`. При недоступности HA показывать локальные данные UPS, затем автоматически возвращаться в HA. Полный поиск по музыкальной библиотеке и управление очередью входят в первый выпуск.

## 2. Архитектура

```text
                         ┌─────────────────────────────────────────┐
                         │ Lenovo 720 · Home Assistant 2026.10.4   │
                         │ http://192.168.50.117/ (Port 80)        │
                         │ Home Console: 6 Views                  │
                         │ NUT integration + Music Assistant      │
                         └──────────────────┬──────────────────────┘
                                            │ local network
                        ┌───────────────────┴───────────────────┐
                        │                                       │
             ┌──────────▼──────────┐                  ┌─────────▼────────┐
             │ Raspberry Pi 4      │                  │ Other browsers   │
             │ cage + Chromium     │                  │ PC / phone       │
             │ 5" Touch 1024×600   │                  │ Home Assistant   │
             │ + NUT Server        │                  └──────────────────┘
             └──────────┬──────────┘
                        │ USB (usbhid-ups)
                   ┌────▼──────────────┐
                   │ APC Back-UPS      │
                   │ BX750MI           │
                   └───────────────────┘

NUT Server on Pi ──────────> NUT integration in HA ──> UPS View
Music Assistant (HA/MA server) ─────────────────────> Music/Radio Views
NUT Server on Pi ──────────> Local PeaNUT fallback ─> Pi display during HA outages
```

**Принцип надёжности:** NUT (`nut-server`, `ups-autodetect.service`, `ups-snmp.service`) — независимый набор системных служб. Графический интерфейс (`ups-kiosk.service` / `cage` / Chromium), PeaNUT и панели HA не должны быть зависимостями цепочки безопасного завершения работы UPS/устройств.

Восстановление киоска должно работать на протяжении всего сеанса. Shell-цикл ожидания HA с последующим `exec chromium` проверяет только запуск. `Restart=always` обрабатывает завершение процесса, но не обнаруживает работающий браузер на странице ошибки.

```text
Start kiosk --> Local UPS fallback --> HA dashboard confirmed ready
                       ^                       |
                       | HA unavailable,       |
                       | browser error,        |
                       | or readiness timeout  |
                       +-----------------------+
Local fallback unavailable --> Visible offline screen + bounded retries
```

Использовать один небольшой контроллер браузера внутри существующей службы киоска. Он управляет Chromium и состоянием повторных попыток. Повторно использовать доступные средства платформы и среды выполнения. До выбора деталей подтвердить способ проверки готовности браузера и перезагрузки страницы; перед добавлением производственной зависимости запросить разрешение. Возврат в HA должен работать и при отказе Docker или PeaNUT. Восстановление может перезапускать браузер киоска, но не NUT и не Pi.

## 3. Структура единой панели Home Console

Создать в Home Assistant **одну новую панель с нуля** (`Home Console`) с шестью представлениями внутри, адаптированными специально для 5-дюймового экрана Pi `1024×600`. Такая структура позволяет переключать страницы одной панели свайпами.

| № | Представление / пример пути | Содержимое | Особенности для 1024×600 |
|---|---|---|---|
| 1 | **UPS** (`ups`) | Состояние (`sensor.ups_apc_status` / `sensor.ups_apc_status_data`), заряд батареи % (`sensor.ups_apc_battery_charge`), нагрузка % (`sensor.ups_apc_load`), входное напряжение (`sensor.ups_apc_input_voltage`), а также включённые сущности `battery_runtime` и `battery_voltage` интеграции NUT | 3–5 крупных показателей (включая оставшееся время); график при наличии места |
| 2 | **Home** (`home`) | Пять подтверждённых групп: (1) состояние/батарея замка, (2) розетка/мощность аквариума, (3) включение/движение/слежение Xiaomi C400, (4) питание/громкость/источник TV–HEOS Denon, (5) входы телевизора LG в гостиной (`PC`, `SHIELD`, `Denon`) + 4 приложения (`YouTube`, `Plex`, `Netflix`, `Apple TV`) и кнопка Выкл | Сохранить порядок пяти групп; на `Home` разрешена вертикальная прокрутка. Замок — только просмотр. Штатное управление Denon и LG webOS независимо от выбранной комнаты MA |
| 3 | **Now Playing** (`now-playing`) | Обложка, трек/радиостанция, Play/Pause, Next, громкость, выбранный плеер (`input_select.pi_console_player`) | Крупные элементы управления и минимум текста |
| 4 | **Music Library** (`music-library`) | Альбомы, исполнители, плейлисты, поиск (сенсорная клавиатура браузера `EN + RU`), очередь | На маленьком экране возможна вертикальная прокрутка |
| 5 | **Players** (`players`) | Выбор целевого плеера/комнаты (`input_select.pi_console_player`, по умолчанию `Denon AVC-X4700H`), состояние, громкость/отключение звука, отдельная явная кнопка «Перенести воспроизведение в комнату» и группы, если поддерживаются MA | Четыре проверенных плеера MA: `media_player.denon_avc_x4700h_3`, `media_player.bedroom_3` (Linkplay WiiM Ultra), `media_player.lg_tv_oled83c_2`, `media_player.shield_3` |
| 6 | **Internet Radio** (`radio`) | 4 существующие избранные станции Radio Paradise FLAC (`Radio Paradise (flac)`, `Mellow Mix`, `Global Mix`, `Beyond...`) в виде крупных кнопок быстрого запуска, плюс доступ к полной радиобиблиотеке MA (~75 станций + Radio Browser) | 4 крупные кнопки избранных станций + просмотр полной радиобиблиотеки MA; запуск воспроизведения в выбранной комнате |

### Правила взаимодействия музыкальных представлений

- Каждая команда воспроизведения, очереди, отключения звука и громкости в `Home Console` адресует комнату, выбранную на консоли Pi. Показывать её рядом с элементами управления.
- Поскольку панель `Home Console` выделена специально для 5-дюймового экрана Pi (а браузеры ПК и телефонов по `D9` используют отдельную основную панель), хранить выбранную на Pi комнату в выделенном только для Pi помощнике HA (`input_select.pi_console_player`) со стартовым значением по умолчанию **`Denon AVC-X4700H`** (`media_player.denon_avc_x4700h_3`). Панели ПК/телефона не должны привязываться к `input_select.pi_console_player`.
- Выбор другой комнаты изменяет `input_select.pi_console_player` и переключает цель управления без переноса, остановки или перезапуска существующего воспроизведения. На представлении `Players` добавить отдельную явную кнопку **«Перенести воспроизведение в комнату»** (`music_assistant.transfer_queue`). Свайпы не отправляют команд воспроизведения.
- Сохранять выбранную комнату после свайпов, перезагрузки страницы и рестарта киоска через `input_select.pi_console_player`. Если комната недоступна, показать это и потребовать другой выбор; не перенаправлять воспроизведение незаметно.
- Не переключаться автоматически на другую комнату только потому, что там началась музыка. Если оцениваемая карточка по умолчанию включает `auto_follow`, отключить его для явного выбора комнаты.
- Встроенные карточки Media control привязаны к отдельным сущностям. Использовать шаблоны/условную привязку или карточку Music Assistant, синхронизированную с `input_select.pi_console_player`, чтобы все четыре музыкальных представления (`now-playing`, `music-library`, `players`, `radio`) следовали одной выбранной комнате.
- До переключения Pi подтвердить поиск, команды очереди, радио, явный перенос очереди и выбор комнаты под `pi-kiosk`. После выхода из представления и возврата поведение должно сохраняться.
- Обеспечить ввод только касаниями на **английском и русском (`EN + RU`)** при `1024×600` через лёгкую виртуальную клавиатуру уровня браузера Chromium/интерфейса, чтобы существующий однооконный Wayland-киоск `cage` оставался без изменений. Поиск не должен зависеть от физической USB-клавиатуры.

## 4. Компоненты и зависимости

### Обязательные компоненты для требуемого интерфейса

1. **Панель Home Assistant** — Встроенная возможность; создать отдельную панель через *New dashboard from scratch*.
2. **[Kiosk Mode](https://github.com/NemesisRE/kiosk-mode)** через HACS — Скрывает заголовок и боковое меню HA. Поскольку живая версия HA подтверждена как **`2026.10.4`**, нужна **Kiosk Mode `15.0.0+`** для HA `2026.10.1+`.
3. **[Home Assistant Swipe Navigation](https://github.com/zanna-37/hass-swipe-navigation)** через HACS — Переключает представления свайпами. Использовать поддерживаемую ветку `zanna-37` вместо старого проекта `maykar`. Выбрать и записать точную версию, проверенную в Chromium на Pi.
4. **Cage + режим киоска Chromium** на Raspberry Pi — Уже установлены и работают через `ups-kiosk.service` (`/usr/bin/cage -d -s -- /usr/local/bin/ups-kiosk-browser`). Скрывают элементы браузера и курсор мыши; это *другой* механизм, чем HACS Kiosk Mode.

### Уже доступно

- **Интеграция NUT в HA** — Не устанавливать повторно.
- **Music Assistant + Radio Browser** — Не устанавливать повторно. Использовать существующие сущности `media_player.*`, провайдеры и сохранённые радиостанции.
- **Инфраструктура киоска Wayland на Pi** — `cage`, `chromium`, пользователь `upsdisplay`, тема скрытого курсора (`/usr/local/share/ups-kiosk/icons`) и `ups-kiosk.service` уже развёрнуты и работают.

### Обязательная проверка реализуемости музыкального интерфейса

- При подходящей функциональности использовать встроенные карточки HA для UPS, домашних устройств и простого состояния плееров.
- Оценить **[Music Assistant Browser Card](https://github.com/PMizz13/ma-browser-card)** по D2–D4 и установленной версии сервера MA. Текущие требования включают MA `2.8+`. Полный доступ к очереди использует токен MA; работа обычного просмотра ещё не доказывает работу управления очередью.
- Проект хранит `ma_token` открытым текстом в конфигурации панели. Использовать ограниченную учётную запись MA, если это поддерживается и проверено. Не включать секреты в Git, скриншоты, диагностический вывод и общие экспорты. Не использовать административный токен HA вместо токена MA.
- Проверить выбранное прямое соединение с MA или HA-ingress под неадминистраторской учётной записью киоска. Проверить библиотеку, обложки, очередь и разрешённые плееры. Рабочий сеанс администратора не доказывает доступ пользователя киоска.
- Не предполагать, что отдельные экземпляры карточки разделяют выбранный плеер. Записать поддерживаемый механизм или необходимую небольшую интеграцию. Если карточка не выполняет правила, до продолжения показать ограниченный по объёму адаптер либо запросить изменение структуры представлений. Не объединять шесть представлений без согласования и не поддерживать непроверенную копию кода карточки.
- Выбрать способ сенсорного ввода и продемонстрировать отправку/очистку поиска, закрытие клавиатуры и прокрутку. Указать нужный пакет или карточку, проверить совместимость с Cage и получить разрешение до установки.
- Записать интерфейс, закреплённые версии компонентов, механизм выбора комнаты, ввод, соединение и обращение с секретами. **Не переключать Pi, пока эта проверка не пройдена.**

#### Политика отказов и восстановления во время работы

Временные пределы ниже — **предлагаемые критерии приёмки**, а не измеренные результаты. До испытаний записать согласованные изменения.

| Условие | Требуемое поведение | Предлагаемый предел |
|---|---|---|
| Загрузка при недоступном HA | Открыть локальный PeaNUT, восстановить вход с проверкой адреса и продолжать проверять HA | Рабочий локальный экран UPS за 30 секунд после старта киоска, если локальные NUT/PeaNUT готовы |
| Отказ HA после запуска, включая страницу ошибки при переходе | Обнаружить отказ; показать локальные данные UPS с указанием недоступности HA | Переход на резерв за 60 секунд устойчивого сбоя |
| Восстановление HA | Подтвердить стабильную доступность и загрузку авторизованной панели; вернуться в UPS | Не позднее 120 секунд после полной готовности HA |
| Истёк сеанс HA или отказано в доступе | Показать необходимость входа и сохранить резервный интерфейс UPS; выполнить поддерживаемую повторную авторизацию | Без подбора паролей, подстановки токенов и циклов перезапуска |
| Дополнительно отказал PeaNUT/Docker | Видимый экран отсутствия связи со статусом повторных попыток; независимое восстановление HA | Без пустого ожидания и перезапуска NUT/Pi |
| Браузер завершился аварийно или завис | Перезапускать только браузер/киоск с ограниченным увеличением интервала | Предлагаемые интервалы: 5, 15, 30, далее не чаще одного раза в 60 секунд |
| Оба интерфейса доступны | Оставаться в HA; не перезагружать исправные страницы и не прерывать ввод | Без безусловной периодической перезагрузки |

Использовать тайм-ауты проверок и несколько последовательных успешных результатов перед возвратом. Записывать изменения состояния, а не каждый опрос. При остановке киоска отменять операции и завершать принадлежащие ему процессы с ожиданием их завершения. Недоступное или устаревшее значение UPS должно быть помечено; не отображать неудачное чтение как `0`, `100%` или Online.

Обновлённая ночная политика: каждое касание продлевает таймер; удержание сохраняет подсветку, отпускание начинает полный интервал бездействия 120 секунд. Первое касание пробуждения по-прежнему перехватывается.

## 6. Безопасность и ограничения

- Не предоставлять доступ к NUT из WAN. Ограничить TCP-порт **3493** локальной сетью и разрешёнными клиентами.
- Использовать отдельную неадминистраторскую учётную запись HA (`pi-kiosk`) для сенсорного экрана. Не использовать администратора на доступном другим людям дисплее. Скрытие меню Kiosk Mode — **не управление доступом**.
- Не хранить пароль HA в shell-скриптах или аргументах Chromium. Защитить `/var/lib/ups-kiosk/chromium` и его копии правами ОС. Профиль может содержать токены HA и сеансы PeaNUT; не включать его в Git и не передавать другим.
- Привязать порт отладки Chromium (`9222`) строго к loopback (`--remote-debugging-address=127.0.0.1`). Проверить слушающий сокет. Удалять порт только после замены и проверки всех зависимых функций восстановления и входа в резервный интерфейс.
- При использовании MA Browser Card учитывать открытое хранение `ma_token` в YAML; не публиковать токен в GitHub, скриншотах и общих ссылках.
- Для стабильности и срока службы накопителя избегать избыточных записей логов и тяжёлых фоновых страниц на Pi.
- Обновлять сторонние компоненты HACS **только после** подтверждения совместимости с установленным HA.
- Подтвердить доступ неадминистраторского пользователя киоска. Скрытые меню, диалоги подтверждения и видимость представлений относятся к интерфейсу, а не обеспечивают права на сущности.
- Ограничить помощник PeaNUT точным loopback origin и путём входа. Не расширять его для подстановки учётных данных HA. Сохранить защищённые файлы учётных данных и данных PeaNUT для резерва и отката.
- Использовать существующие HTTP-адреса только в доверенной локальной сети. Изменение транспорта или внешнего доступа требует отдельного проектирования и проверки.

## 8. Отказоустойчивость и быстрый откат

1. Если **Swipe Navigation** нестабилен, отключить/удалить его ресурс HACS. Обычная навигация по вкладкам/представлениям остаётся в браузере; на Pi временно открыть панель без `?kiosk`.
2. Если **Kiosk Mode** не работает, убрать `?kiosk` из URL в `/usr/local/bin/ups-kiosk-browser`. Сама панель сохраняется.
3. При более общих проблемах киоска HA выполнить полную процедуру отката ниже. Автоматический резерв при сбое не заменяет восстановление проверенной конфигурации.
4. При недоступности HA использовать локальный резерв UPS и отдельно проверять Hyper-V/сеть Lenovo. **NUT продолжает работать на Pi.**
5. Постоянно сохранять PeaNUT и его данные для D1. На время перехода сохранить `ups-web.service`. Отказ от автоматического резерва требует нового решения пользователя и замены с теми же успешными испытаниями.

### Откат панелей HA — независимо от Pi

До изменений D9 сохранить закрытые копии конфигурации/метаданных каждой панели, регистраций ресурсов и стартовых настроек/бокового меню с проверенным способом восстановления. При необходимости сохранить статус автоматического формирования; не считать такой интерфейс отсутствующей ручной конфигурацией.

При регрессии восстановить конкретную панель через поддерживаемое редактирование/API HA, затем изменённые названия, видимость бокового меню и стартовые настройки затронутых пользователей. Общий ресурс восстанавливать только после проверки версий, нужных другим панелям. После восстановления проверить старые URL и домашние элементы управления. При откате только разметки не менять профиль киоска Pi, NUT и интеграции устройств. Полную копию HA использовать лишь при недостаточности точечного восстановления.

### Полная процедура отката киоска Pi

Все пути ниже относятся к закрытой копии этапа 0, дополненной копией остановленного профиля браузера на этапе 3. До переключения проверить наличие установленного скрипта запуска, unit-файла, службы/таймера/помощника входа, каталога readability, профиля Chromium, метаданных и исходных состояний автозапуска.

1. Проверить полноту копии и соответствие записанным хешам. Не перезаписывать работающую установку из неполной копии.
2. Убедиться, что Docker и существующий контейнер `ups-peanut` работают. Это обязательно и в случае, если PeaNUT ранее остановили. Сохранить текущие учётные данные и постоянные данные:

   ```bash
   sudo systemctl start docker.service
   sudo docker start ups-peanut
   curl --fail --silent --show-error --max-time 3 http://127.0.0.1:8080/api/ping
   ```

   Разрешить контейнеру до 60 секунд для готовности. Если он недоступен, проверить Docker/PeaNUT до возврата скрипта, который ожидает его запуска. Не перезапускать NUT ради восстановления веб-интерфейса.
3. До восстановления файлов или профиля остановить действия браузера:

   ```bash
   sudo systemctl stop ups-kiosk-login.timer ups-kiosk-login.service ups-kiosk.service
   ```

4. Восстановить из записанной копии установленный `/usr/local/bin/ups-kiosk-browser`, `/etc/systemd/system/ups-kiosk.service`, входные `.service`/`.timer`, помощник и каталог readability. Сохранить владельцев и права выполнения. При необходимости вернуть профиль остановленного браузера; перед заменой закрыто сохранить текущий профиль. Не объединять активный профиль и не оставлять новые файлы расширения в восстановленном каталоге.
5. Перечитать unit-файлы и вернуть исходный автозапуск. В проверенной исходной системе автозапуск киоска и таймера входа включён:

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now docker.service ups-kiosk.service ups-kiosk-login.timer
   ```

   Помощник входа — статическая oneshot-служба; включать её таймер, а не пытаться включать саму службу. Подтвердить сохранение записанной политики перезапуска контейнера `unless-stopped`.
6. Проверить открытие `http://127.0.0.1:8080/device/ups`, восстановление входа с проверкой адреса и совпадение показаний с `upsc ups@localhost`. Проверить активность NUT/SNMP и хеши конфигурации. Завершить контролируемой перезагрузкой и повторить проверки.

При пробном откате записать точные команды копирования/восстановления с реальным путём копии и всеми установленными файлами восстановления. Неиспользуемый файл помощника может остаться, но новый процесс или таймер восстановления не должен продолжать мешать возвращённому скрипту запуска.

- ОС/оборудование Pi: Debian 13 `aarch64`, `1.8 GiB` RAM, `DSI-1` в режиме `1024×600 @ 59.94 Hz`.

## 10. Последовательность реализации (кратко)

1. **Копии и инвентаризация (Этап 0):** Повторно проверить оборудование Pi и записать закрытые места хранения копий/отката HA и Pi.
2. **Реализуемость:** Подтвердить полный поиск, управление очередью, общий выбор комнаты через `input_select.pi_console_player`, сенсорный ввод `EN + RU` через браузерную клавиатуру и права `pi-kiosk`. До установки получить разрешение на конкретные новые производственные зависимости.
3. **HA (Этапы 1 и 1A):** Включить сущности времени работы/напряжения NUT, создать `Home Console` с шестью представлениями `1024×600` и проверить их под `pi-kiosk`. Завершить очистку отдельной адаптивной панели ПК/телефона на Этапе 1A с подтверждениями до/после и точечным откатом.
4. **Pi (Этапы 2 и 3):** Скопировать профиль остановленного браузера. Развернуть восстановление во время работы, браузерную клавиатуру `EN + RU` и ночное управление подсветкой (`07:00–23:00` / пробуждение касанием ночью) вокруг существующего киоска Cage/Chromium. Сохранить PeaNUT, вход с проверкой адреса и readability. Один раз войти в HA под `pi-kiosk`.
5. **Приёмка (Этапы 4 и 5):** Проверить сенсорный ввод, слышимое воспроизведение, явный перенос очереди, включение и выбор источника Denon/LG TV, запуск, резерв, автоматический возврат и неизменную работу NUT. Выполнить полный пробный откат.
6. **Наблюдение:** Завершить 24–48 часов мониторинга, затем описать эксплуатацию и обновления. Сохранить локальный резерв UPS и проверенные копии.
